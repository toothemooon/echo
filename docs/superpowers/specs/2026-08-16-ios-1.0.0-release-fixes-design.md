# iOS 1.0.0 Release Fixes Design

## Goal

Prepare the current iOS 1.0.0 candidate by fixing the four conflicting Japanese quote records, synchronizing published counts and App Review documentation, making Clear All deterministic in the presence of unfinished asynchronous writes, and allowing startup to continue with system typography when the bundled font fails to load.

## Confirmed Scope

This change will:

1. Keep Historical Echo visible.
2. Correct and deduplicate the four confirmed Japanese attribution conflicts.
3. Update `QUOTE_CONTEXTS.json` to match the corrected quote catalog.
4. Update current catalog counts and App Review/TestFlight documentation.
5. Serialize active `@echo/` storage mutations with Clear All through one minimal global queue.
6. Add an explicit regression test in which an unfinished asynchronous write overlaps a clear operation.
7. Treat a font-loading error as startup-ready and use the system quote font for that runtime session.
8. Update `docs/problem.md` so its iOS 1.0.0 decision reflects the user's decision not to hide Historical Echo and not to freeze the four JSON files.

This change will not:

- hide or remove Historical Echo as a feature;
- add Git LFS, artifact manifests, checksums, or other release-data infrastructure;
- modify or restore `.playwright-mcp`;
- fix Android, Web, Batch pipeline, package-size, dependency-audit, or unrelated accessibility findings;
- introduce a storage framework, cancellation framework, transaction abstraction, or dependency-injection container.

## Clear All Design

### Root cause

Each storage module currently owns an independent promise queue or writes directly to AsyncStorage. `clearLocalData()` only removes keys visible during one `getAllKeys()` snapshot. A mutation started before Clear All can therefore finish after `multiRemove()` and recreate a key.

### Minimal coordinator

Add one dependency-free module under `src/storage/` containing a single process-wide promise tail:

```ts
export function enqueueStorageMutation<T>(
  operation: () => Promise<T>,
): Promise<T>;

export function waitForStorageMutations(): Promise<void>;
```

`enqueueStorageMutation` appends the operation synchronously when the public mutation function is called. A rejected mutation must not poison later queue entries. No priorities, cancellation tokens, epochs, transactions, or retries will be added.

The active production mutation paths will use this queue:

- saved quote read-modify-write operations;
- viewed quote record/clear operations;
- the complete quote recommendation read-select-write operation;
- preference setters;
- `clearLocalData()` itself.

`saveExposure()` remains a direct write because it executes inside the globally queued recommendation operation; wrapping it again would create nested queue deadlock. Dormant `definingMoment` storage is outside this release scope because it has no production caller.

When Clear All is requested, its removal operation is appended to the same queue. Operations invoked earlier finish first and their keys are then removed. Operations explicitly invoked after Clear All completes are legitimate new user state and may write normally.

`clearLocalData` will accept an optional minimal storage interface for tests while defaulting to AsyncStorage in production. This avoids mocking the React Native package and keeps the race test focused on real queue ordering.

The icon reset remains outside the storage queue. An icon-sync failure will not change the reported result of a successful data clear.

## Clear All Regression Test

The regression test must exercise the original race, not only inspect queue internals:

1. Create an in-memory storage implementation containing an `@echo/` key.
2. Enqueue a write operation that waits on a manually controlled promise before writing another `@echo/` key.
3. Call `clearLocalData(inMemoryStorage)` while that write is unfinished.
4. Assert that the clear promise has not completed prematurely.
5. Release the pending write.
6. Await both operations.
7. Assert that no `@echo/` key remains.
8. Assert that a non-ECHO key remains untouched.

Additional tests will confirm that one rejected mutation does not prevent the next queued mutation or Clear All from running.

## Font Failure Design

The font hook result will include both `fontsLoaded` and `fontError`.

Startup font readiness is:

```ts
fontsLoaded || fontError != null
```

While the font is still loading and no error exists, the splash remains. When loading succeeds, current behavior is unchanged. When loading fails, startup proceeds and the runtime quote-font selection resolves to `system`; the persisted user preference is not overwritten.

A small pure startup helper will express these two decisions so Node tests can cover:

- loading and no error is not ready;
- loaded is ready;
- error is ready and selects the system quote font;
- success preserves the stored quote-font preference.

No new loading UI, retry framework, font package, or global typography refactor will be introduced.

## Testing Strategy

Implementation will follow red-green-refactor:

1. Update quote tests with the desired 1,820/3,925 counts, NFKC/punctuation-normalized uniqueness, correct retained attribution, and absence of deleted IDs; run and observe failure.
2. Update context tests with the desired 3,925 count, deleted-ID absence, and corrected `author_ref`; run and observe failure.
3. Add the unfinished-write-versus-clear regression test and observe the current implementation fail.
4. Add startup readiness/font fallback tests and observe them fail because the helper does not exist.
5. Apply the minimum data and code changes needed to turn each test green.
6. Run all tests, TypeScript, Expo Doctor, and an iOS production export.
7. Re-run normalized duplicate, catalog-count, context-count, and documentation-number checks.
